# Guogaology 0.4.1 — inventory, travel, manuscripts and ores

User report, 2026-10-07: the manuscript inventory button obscures the vanilla recipe-book toggle. The user also requests a proposal for book-material availability in the Outer and Inner realms; that proposal is not authorization to implement new recipes or generation.

## Change

The survival inventory manuscript button now sits to the right of the vanilla recipe toggle, with a six-pixel gap. Its width is 42 pixels; both Chinese and English labels fit. The existing per-frame origin update follows the inventory panel when the recipe book opens or closes. The creative inventory position is unchanged.

## Portal feedback and search

User follow-up: `/googology visit` appears unresponsive for several seconds. A longer visible “Loading terrain…” screen is acceptable, but an unexplained pause is not.

The previous path already requested a bounded 3×3 destination window asynchronously and joined futures only after `isDone()`. Its fixed eight search steps per tick still spent 37–54 ticks inspecting all 48–71 columns and roughly 240–350 candidate sites even when the closest supported footprint was valid. New terrain generation and destination rendering remain additional real costs.

Changes shared by all four source targets:

- A token-bound S2C start packet is sent before destination chunk preparation. The client opens Minecraft's actual, nonpausing terrain-loading screen while the server player remains in the source world. No extra chat or untranslated custom UI is added.
- Successful transfer hands off to Minecraft's normal destination readiness. Modern Minecraft may update/reuse the very same screen; completion therefore does not close it once the source dimension changes.
- Cancellation, frame damage, death and failed chunk loads discard only the matching request and its own screen, preserving unrelated menus and newer requests. Prewarming displays no screen and builds no exit.
- Search still prefers nearby registered safe gates, then naturally supported empty footprints, then a bounded safe-platform fallback. Because candidates are sorted by full 3D distance, the first supported site is already optimal and ends the search immediately.
- Search uses at most64 steps per server tick and a shared soft2ms deadline. Each step is independently bounded; a step already in progress can run past that soft deadline. There are no unfinished future waits, broad synchronous terrain scans or destructive forced exits.
- Server preparation expires at600 ticks or45 seconds of wall time and safely retreats on failure. A60-second client watchdog prevents a lost reply from leaving this pending screen indefinitely. Actual native destination readiness retains its own Minecraft timeout.

The loading packet authorizes presentation only; all placement, cancellation and actual travel remain server-side. Nearby already-ready gates keep their direct fast path.

## Book-material proposal — not implemented

Follow-up: the user briefly requested three Laver Ribbons → one paper, then cancelled that recipe before implementation. No book-material recipe has been added; the suggestions below remain only a discussion record.

The existing Outer-realm Busy Beaver drops 8–16 paper and 1–2 leather. Inner biomes do not spawn that creature. This supplies occasional books but leaves no ordinary plant/wood crafting route in either realm.

Recommended recipes, all producing native Minecraft items:

- Three Laver Ribbons → three paper: a natural use for the existing thin plant material. One Giant Laver already crafts into four ribbons.
- Three ordinary/mod logs → six paper: a general wood-pulp route so basic books do not depend on finding the Laver biome or a specific creature.
- Three paper + one ordinary/mod plank → one book: a wood-cover binding alternative to the retained vanilla leather recipe.

This needs no new paper, book or cover item and works with normal book-consuming recipes. The proposal leaves recipes, creature drops and world generation unchanged until the user chooses to proceed.

## Additional confirmed changes, 2026-10-07

- Manuscript Empty Set sockets have no durability benefit. Runtime already excluded that channel; the right-hand menu was incorrectly calculating the equipped-item version. Both now use the same carrier-aware guard. Item wear is still independent of the held manuscript's Empty Set sockets.
- Pick/sword Branch wording uses vanilla Fortune/Looting names, including tooltips and the station panel. Bow Branch wording uses its actual Infinity/Multishot/Piercing abilities, rather than suggesting it grants Fortune or Looting. Native enchantment translation keys supply localized names.
- Additional excavation skips every candidate whose Y is below the originally broken block. Its count, closest-first plane search, loot, durability, sneaking bypass and other eligibility checks remain unchanged.
- Every manuscript tier accepts ordinary Totems of Undying in its existing sockets, one item per socket. These are consumables, not numeric core grades, and occupy real saved item-component slots. Tools and armor reject them. With active Guogao II/III, inventory totems are consumed first; otherwise, or when the inventory is empty, a socketed totem in the active held manuscript rescues the player. Offhand manuscript priority and the native bypass-invulnerability exclusion remain.
- New socket contents activate only on closing the editing screen. When an already active socketed totem triggers during editing, an owned item is consumed before debiting the read-only activation snapshot. A removed active totem still on the cursor/inventory can pay this cost, but a snapshot alone cannot resurrect the player. Real slot changes are synchronized so closing/death cannot restore a spent totem. The original totem resurrection effects are retained.

Ore policy is a deliberate overlay on the preserved Alice reference data. `tools/generate_ore_distribution.py` owns it, and `prepare_outer_resources.py` applies the same policy after every target's resource conversion; regenerated resources must not silently restore the old ore counts. Vein sizes, host blocks and biome membership are unchanged. Existing `_hell` definitions receive the same values without adding ores to a dimension that did not already use them.

At inner1, the native implementation's actual upper sampled Y is one below the upper anchor. Γ should have less than0.3% of height candidates at or above Y=50; Ω is deeper. Actual yield also depends on replacement stone, bedrock, caves and vein overlap. The 2× attempts / 50% exposure cancellation describes the unchanged ω/ε height profiles; Γ/Ω are additionally redistributed vertically. Existing chunks are not rewritten.

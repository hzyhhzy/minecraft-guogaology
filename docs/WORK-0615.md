User requests equipment hover text consisting only of the item name, short non-quantitative abilities, used/total core slots and two installed cores per row. This change applies to picks, swords, bows, armor and manuscripts. Effect formulas, enhancement previews, registered IDs and item components stay unchanged.

## Display contract

All seven legacy/common append overrides delegate to the same compact structure. Known installed cores use a dedicated localized short name followed by `:LvN`; ordinal raw levels2/3/4 retain displayed grades1/2/3, while the base crystal remains a crystal. Empty sockets are omitted from the list, but duplicate and unknown installed items retain their original order and ownership. An odd last entry gets its own row.

The optional capabilities section lists discrete mechanics such as Infinity, Multishot, Piercing, Fortune/Looting, Silk Touch, pattern mining, impact bursts, on-hit debuffs, flight and immunity. Long capability text wraps with the actual client font; installed-core rows still contain two entries each. Pure attack, speed, wear, armor, health, reach and jump numeric bonuses are not replaced with prose. Empty equipment has no invented capabilities row. Silk mode advertises Silk Touch instead of Fortune; effective profiles exclude incompatible or enchanted mixed cores.

The client-only `EquipmentTooltipAttributesMixin` suppresses only native attribute tooltip output for `MiningContent.GEAR`. It also wraps just our top-level capabilities row at the smaller of320logical font pixels and screen width minus24, using native logical text splitting and preserving segment styles. Core rows, custom names and other tooltip objects are not rewritten. Actual attribute components, calculations, enchantment rows, custom lore and advanced F3+H information are not changed. Vanilla items and third-party additions retain their own presentation. Enhancement previews keep their existing detailed effects.

Raw installed contents are read directly for display. Effective-profile reads use an owned ItemStack copy because legacy Absence normalization may replace a component list; the existing normalizer copies affected nested stacks before editing. Hovering must not normalize the player's real item.

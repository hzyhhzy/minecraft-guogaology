# 0.6.4 — 一级空无晶核旧状态清理

用户于2026-10-20授权实施此前的兼容方案，明确fffZ/FOS和ψ/Z的稳定机制不能改变。本轮不发布GitHub、不合并0.6.4到main。

## 基线与范围

- 正式0.6.3：`5194764e33be0dba5028e31158837aeab595f163`。
- 完整备份：`codex/backup-0.6.3-before-absence-core`；开发：`codex/0.6.4-absence-core-compat`。
- 已按先前授权将真正的`main`快进到0.6.3；没有包含已放弃的0.6.3.1建筑资源块试验。
- 本轮仅修改一级空无晶核及其旧物品组件的读取清理，不调整原材料、配方、战利品、建筑或晶核数值。

## 兼容约定与实现

1. `guogaology:lho_trace`的方块和物品ID不变。独立的`AbsenceCoreBlock`保留旧`stable`、`anchored`、`player_placed`三项Boolean方块属性，八种旧状态均继续可解码。成品晶核不再继承原料`AnchoredBlock`的接触消失、锚定扫描、稳定限定掉落行为。保留原外观和固定100tick挖掘规则。
2. 新采集和创造选取产出普通晶核，不写入上述三个旧状态。旧物品载入、复制及原版组件补丁应用时，仅从精确`guogaology:lho_trace`的`minecraft:block_state`里移除这三个键；空组件才整体删除。名称、数量、其他组件及未知状态键保留。
3. 已安装晶核列表增加同样的惰性清理，逐个复制变更的目标物品，不更动原列表共享的对象，不移动空槽，不改变镶嵌数。安装和拆回也经过同一入口。
4. ItemStack构造器仅注入所有非空物品途径汇合的三参数构造器，排除初始化`EMPTY`的Void构造器；辅助函数不依赖模组内容注册类。四版映射分别适配，1.21.11的ItemLike与26.x的Holder内部参数分开处理。
5. 原料`AbsenceBlock`、`AnchoredBlock`、`OrdinalAnchoring`、`VanishingHydraBlock`以及fffZ/FOS/ψ/Z的注册和资源保持不变。已放置晶核的兼容属性不会再作为可采集的成品差异。

- `absence064-baseline-a`：精确0.6.3正式JAR（SHA-256 `b84845a3fdab69fcfb52950aa2da3ffaf8851eef4054bfbf6860e96e85832a84`）建立真实测试世界，保存八种旧方块状态、六份箱内物品、四份玩家物品及单独旧NBT。旧版设备先完成其原生缓存刷新，随后仍确认嵌入物有旧标记。283项原生检查通过，成功停服保存。
- `absence064-upgrade-a`：0.6.4打开上述世界副本，589项原生检查通过。八种旧区块状态逐项保留；旧磁盘/箱子/玩家物品及已安装槽位一致，名称、损伤、其他自定义组件和未知状态键保留。17+19颗仅旧标记不同的晶核通过原版容器合堆为36颗。
- 逐个八状态验证接触和右键不会移除成品、空手/木棍/钻石镐及急迫/挖掘疲劳均为100tick，实际生存挖掘与原版掉落表均只产出一个无旧标记的晶核；两种创造选取路径均正确。Lv1/2/3真实配方及旧物品安装/拆出守恒通过。
- 验证惰性清理不修改调用者的原列表/原晶核对象，保留空槽和非目标对象；重复读取保持列表身份，不反复刷新属性。
- fffZ/FOS/ψ/Z各八种状态共32组：原生碰撞、右键、连锁销毁回调、完整掉落组件、碰撞及选中轮廓与精确0.6.3对照相同；另验证放置与手持序数晶体在二格立方体角落的保护。相关生产类和资源在四份二进制中均逐字节未变。

# 0.6.12：可编辑挖掘图案

2026-10-25。用户授权实施此前确认的5×5连锁挖掘图案，在独立分支开发并替换fo262；不合并main，不push，不发Release，不替换fo263_2，背包暂不处理。前置main为62b6c6d，备份分支codex/backup-0.6.11-before-mining-pattern；开发分支codex/0.6.12-mining-pattern。

## 约定

- 矩阵晶核Lv1/2/3额外预算1/2/4，各维度相同，同镐平方求和开根号再向下取整。
- 强化台内的二级图案页保持原菜单和实物所有权；一个参考格与若干额外格保存在镐上。
- 5×5始终竖直，上方世界+Y，左右按挖掘开始时的水平朝向选择四个方向；俯仰与点击面不改变平面。取消旧禁止向下限制。
- 原目标映射参考格；仅尝试选定位置，不会用其它位置补足空气、不适合或被保护的格。
- 下蹲跳过连锁，保留权限、正确工具、掉落、经验、耐久、区块已加载及非递归判定。
- 用户随后提供2～12总格数（含参考格）的精确默认图案。每次额外预算变化就自动重置为该默认值，预算不变才保留自定义；不保留或显示禁用格。旧物品缺图案时使用当前默认；显式清空在预算不变时保留。

## 实现和边界

已完成。范围设置只出现在装有矩阵晶核的镐的强化台页；不进入手稿，也未加入背包功能。左键切换额外格、右键设置参考格，清空、重置、返回均由原生菜单按钮请求服务端复核。二级页继续持有原强化菜单和真实物品；编辑时禁止操作底下槽位，ESC返回强化页。容量、距离、玩家身份、存活、持物和非法按钮均校验。

图案保存三个原生CUSTOM_DATA整数：reference、mask、capacity。合法旧数据缺失时只读回退默认；编辑、晶核修改及装备刷新时才写入实际物品。当前容量变化会覆盖旧图案；同容量保留自选和显式空图案。每次开挖在原生START锁定水平朝向，ABORT取消；换世界、断线和停服清理，持物／晶核／图案变动会取消本次额外动作。原块变亮等属性变化不会误取消同一个方块的采集。

白框表示原格，绿框表示客户端根据已加载世界判定的有效额外格；服务端仍独立复核权限，其他模组隐蔽的保护判定不由客户端预测。渲染入口不请求区块，不破坏方块；26.x在抽取时生成不可变数据，提交时只读取几何。

### 中间问题与处理

- 26.2的Fabric世界切换事件已更名为LevelChange，补充明确版本适配；首轮PowerShell未引号目标参数被截断，正确传参后重建。用户追加默认布局时正在进行的旧候选构建不计最终通过。
- 原生红石矿START会改LIT；已将开挖快照的一致性改为方块种类比较，并保留其他上下文锁定，实际变亮控制通过。
- 旧采掘QA缺START且把“右侧”固定当作东侧，按新模式明确方向与图案后保留原经验／精准和软糖罐检查。
- 原生ItemStack整体matches对List<ItemStack>晶核组件使用对象相等，不能作为反序列化后的结构比较。诊断确认只有该层对象身份不同；改为整份原生NBT再编码严格相等、逐晶核原生比较、全部其他组件相等与图案相等同时校验。三份实际NBT均通过，无物品数据损失。
- 26.2旧告示牌截图用例服务端直接放置后，客户端可能先收到打开编辑器再收到替换方块更新。改为客户端等待空气／支撑／持物同步，再执行真正的原生客户端放置；四款自动编辑、双面文本、NBT及掉落检查均保留并通过。未改生产告示牌机制。

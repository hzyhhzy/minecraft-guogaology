# 0.6.7 — 26.3战利品格式与世界加载修复

用户于2026-10-20确认“存档损坏”反馈的现象是打不开，并授权修复和实测。基线为已发布0.6.6／`9422636`，备份分支`codex/backup-0.6.6-before-loot-263-fix`；开发分支`codex/0.6.7-loot-263-compat`。本轮没有合并main、push或Release授权。

## 已确认根因

用户日志来自Minecraft26.3、Guogaology0.6.6。四张巨构主副箱表中的六个`minecraft:tag`条目仍使用旧`name`字段，26.3原生TagEntry要求`items`的HolderSet表示，如`"items":"#guogaology:fruit_guogao"`，因此报`No key items`并阻止注册表加载。该格式由0.6.5新箱表引入，0.6.6沿用；0.6.0～0.6.4的26.3成品中没有这种条目。标签本身及其成员完整。

受影响：`guogao_ruin`／`guogao_sanctum`各一处，`hydra_ruin`／`hydra_sanctum`各两处。它可同时阻止新世界和旧世界打开；用户日志没有正常世界启动／保存标记，不足以证明region、level.dat或playerdata文件已经损坏。

前一轮只读调查已用精确0.6.6JAR的六处条目和26.3原生codec复现：旧格式全部失败，只在内存副本修正字段后全部解码成功。该最小codec夹具使用明确标注的模拟注册表，不能当成完整世界加载或存档升级测试。证据在`build/loot-codec-066-263/`。

## 实施边界

- 只修26.3资源适配器，不把其他三版仍正确的共享源格式改成26.3格式，不改`minecraft:item`的`name`。
- 保留`expand`、权重、抽取与数量函数、标签备选和全部玩法数值；现代格式重复转换应保持不变。
- 最终打包检查递归验证所有相关条目，补精确旧错误、嵌套和幂等回归。
- 不改变注册ID、维度或存档schema，不扫描／重写正常存档，不删箱子或区块，不通过禁用数据包掩盖加载失败。

## 构建与回归保护

四版构建和最终打包检查通过，94项Python检查通过。新检查独立于转换器，递归校验最终包中248张战利品表、6个标签条目、3个标签及20种实际成员，拒绝旧格式、缺失／空／循环标签；用精确0.6.6错误条目验证检查确实会拒绝旧26.3成品。新增6个测试方法覆盖嵌套、权重、数量、幂等、其他版本格式和标签解析。

逐包对照0.6.6：所有Java类和其他二进制保持逐字节相同；除版本元数据、语言／旧版箱表CRLF改LF外，仅26.3上述四张表六处`name`改为`items:#tag`。独立类型敏感JSON和重复键检查确认数量、`expand`和其他语义完全相同，1.21.1内嵌兼容包也只有版本变化。证据`build/loot-067/package-delta.json`。
